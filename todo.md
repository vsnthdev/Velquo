# Velquo — Performance & Bug Fix Backlog

## Bugs & Edge Cases

- [ ] **Fix mismatched state event name in `FileBrowserWindow` (`src/pages/FileBrowserWindow.tsx:84`)** — `FileBrowserWindow` listens to `"velquo://state-changed"`, but the Rust backend emits `"velquo://state-updated"` (`src-tauri/src/kdeconnect/daemon.rs:501`). As a result, live updates to the device's `saveLocation`, name, or online status never reach the open File Browser window.
- [ ] **Clean up partial files on failed incoming KDE Connect file transfers (`src-tauri/src/kdeconnect/daemon.rs:4480`)** — In `download_payload_file`, if the TLS stream drops or times out mid-transfer after `tokio::fs::File::create(dest_path)`, the corrupted partial file is left behind in the user's Downloads folder (unlike `sftp.rs:477`, which removes `dest_path` on error).
- [ ] **Cap `self.transfers` history length (`src-tauri/src/kdeconnect/daemon.rs:4825`)** — `upsert_transfer` inserts every file, URL, and text transfer into `self.transfers` (`Vec<TransferItem>`) without ever truncating old entries. Over long menu-bar sessions, this vector grows unboundedly in memory and inflates every `get_app_snapshot` IPC response.
- [ ] **Cap per-device `album_art_cache` size (`src-tauri/src/kdeconnect/daemon.rs:3916`)** — `DeviceEntry.album_art_cache` (`HashMap<String, String>`) stores 100–300 KB base64 data URLs for every track played on the phone and never evicts old entries while the device remains connected.
- [ ] **Cap frontend `itunesArtCache` size (`src/utils/format.ts:2`)** — `itunesArtCache` (`Map<string, string | null>`) grows without an upper bound across long sessions.
- [ ] **Skip verbose `INFO` packet-body serialization on high-frequency `mousepad.request` packets (`src-tauri/src/kdeconnect/daemon.rs:1928`)** — `handle_incoming_packet` serializes `packet.body` to JSON and logs it at `INFO` level on every packet, including 60–120 Hz trackpad movement (`dx`/`dy`) packets from the phone, causing heavy disk I/O and log churn during remote trackpad use.

## Performance Optimizations

- [ ] **Stop spawning `/usr/bin/perl` twice per 2-second MPRIS poll tick (`src-tauri/src/kdeconnect/daemon.rs:805`, `macos_media.rs:180`)** — The background MPRIS broadcaster calls `get_mac_player_list()` and `query_mac_player_status("")` every 2 seconds, and both functions independently call `query_control_center_now_playing(false)`, spawning **two** `/usr/bin/perl` processes every 2 seconds (60 process spawns/min). Combining them into a single query (and skipping the poll when `is_macos_audio_output_running()` is false and no media was previously playing) cuts idle CPU usage dramatically.
- [ ] **Eliminate per-snapshot `logs` cloning and unused `velquo://log` IPC events (`src-tauri/src/lib.rs:28`, `src-tauri/src/logger.rs:113`)** — `get_app_snapshot` clones up to 400 `LogEntry` structs on every single UI state update even though `src/types.ts` (`AppSnapshot`) never reads `logs`, and `AppLogger::log` emits `"velquo://log"` over Tauri IPC on every log line with no frontend listener.
- [ ] **Keep a persistent buffered log file handle instead of re-opening `app.log` on every log line (`src-tauri/src/logger.rs:98`)** — `AppLogger::log` calls `OpenOptions::new().create(true).append(true).open(&self.log_file_path)` on every log statement (`open` + `write` + `close` syscalls per line). Holding a `Mutex<BufWriter<File>>` avoids repeated filesystem open/close overhead.
- [ ] **Avoid calling `if_addrs::get_if_addrs()` on every `get_app_snapshot` IPC call (`src-tauri/src/kdeconnect/daemon.rs:528`)** — `get_host_info()` enumerates all kernel network interfaces via `if_addrs::get_if_addrs()` on every UI snapshot (including during 120ms file transfer progress ticks), even though the frontend doesn't use `host.localIps`.
- [ ] **Replace `/usr/bin/pmset -g batt` subprocess with native macOS `IOKit` Power Sources API (`src-tauri/src/kdeconnect/daemon.rs:3700`)** — `read_macos_battery_status()` spawns `/usr/bin/pmset` synchronously on the Tokio async worker thread every 30 seconds (`daemon.rs:693`) and on every `kdeconnect.battery.request`. Reading `IOPSCopyPowerSourcesInfo` / `IOPSGetPowerSourceDescription` via `IOKit.framework` FFI runs in-process in `< 50µs` with zero subprocess spawning.
- [ ] **Replace `/usr/bin/defaults read -g AppleInterfaceStyle` with in-process `NSApplication` appearance check and cache rasterized tray icons (`src-tauri/src/lib.rs:610`, `lib.rs:734`)** — `build_tray_menu` spawns `/usr/bin/defaults` and re-parses/rasterizes all Phosphor duotone SVGs via `resvg` every time the tray menu refreshes. Checking dark mode via `objc2` (`NSApplication.effectiveAppearance`) and caching the 36×36 RGBA icon buffers makes tray menu rebuilds instantaneous.
- [ ] **Batch `upsert_transfer` UI notifications when starting multi-file uploads (`src-tauri/src/kdeconnect/daemon.rs:4653`)** — `send_files_to_device` calls `self.upsert_transfer(...)` inside a loop for each file in a batch, which fires `self.notify_ui()` $N$ times back-to-back instead of inserting all $N$ items under one lock and calling `notify_ui()` once.
- [ ] **Coalesce rapid `velquo://state-updated` events in the frontend (`src/App.tsx:162`)** — When multiple KDE Connect packets arrive in the same millisecond burst (e.g., on device connect when battery, connectivity, MPRIS, and notifications all arrive within 10ms), `App.tsx` triggers parallel `invoke("get_app_snapshot")` calls for each event instead of coalescing concurrent snapshot fetches.
